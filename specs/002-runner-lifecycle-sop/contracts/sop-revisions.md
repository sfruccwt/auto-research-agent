## workflow.md 修订

### W1: Motivation 校准步骤（FR-116）

在"第 2 步：第一轮搜索——建立全貌"和"第 3 步：提取观点"之间插入：

```
## 第 2.5 步：Motivation 校准（中途门前必做）

第一轮建图完成后、写判断单前，用搜到的关键发现反问用户：
- "这些发现跟你的实际处境/动机有什么关系？"
- "有没有什么约束是你之前没提到的？"

用户补充的约束记录到 `notes/task-card.md` 的 motivation 区域。

> 要点：motivation 不是开题时一次性写完的。用户看到搜索结果后才会联想到关键约束。
```

### W2: 关键词压测（FR-120）

修改"第 1 步：定义问题"中的流程，在"先写清楚"列表之后增加：

```
### 关键词压测

对"要回答的问题"中每个关键词做范围确认：
- **主语**：谁？（如"人机协作"→ 谁在协作？开发者？终端用户？）
- **领域**：在哪？（如"协作"→ 软件开发？日常办公？创意工作？）
- **动作**：做什么？（如"信任"→ 信任什么？代码质量？决策正确性？）

如果范围不清，主动反问用户确认，不要替用户假设。
```

### W3: 子课题拆分检查（FR-120a）

在中途门（第 3 步之后、第 4 步之前）增加：

```
### 中途门检查：子课题拆分

第一轮广搜完成后，检查是否需要拆分子课题：
- 是否发现某个子概念需要独立研究才能支撑母课题结论？
- 是否有子领域的复杂度超出当前 run 的动作上限？

如需拆分，向用户提示并等待判断。runner 只提示，不自动决策。
```

### W4: 证据链扣紧（FR-121）

在备忘录写作指引（第 5 步或收尾门附近）增加：

```
### 证据链要求

每条来源不仅列名字，还要说明：
- 这个来源说明了什么
- 为什么它支撑这个结论
- 它的证据层级（一手/二手/综述/社区经验）
```

### W5: 路径定义清晰度（FR-122）

在路径比较相关段落增加要求：

```
### 路径定义要求

每条待比较路径必须写明：
1. 人类具体做什么操作
2. 人类不做什么
3. 与相邻路径的分界线

如果两条路径的区分维度不清，先明确区分标准再比较。
```

### W6: memo vs output 区分（FR-119）

在收尾门附近增加明确说明：

```
### memo 与 output 的区分

- **memo**（`notes/memo.md`）：收尾门的中间产物。是研究过程的判断记录，面向研究者自己。
- **output**（`output.md`）：最终投递到 wiki inbox 的成品。由 memo 加工而来，面向读者。

禁止将 memo 直接写到 `output.md` 位置。output 必须经过加工：
- 重组结构（从研究过程叙述改为结论先行）
- 补充对读者的上下文说明
- 展开关键概念
- 移除研究过程性内容（如"第一轮发现..."）
```

### W7: 核心概念展开为全阶段要求（FR-117）

在文档顶部的"先说清"之后，增加全局要求：

```
### 全阶段要求：核心概念清晰描述

在任何阶段的产出中（搜索笔记、判断单、备忘录、output），遇到可能需要展开的术语时：
1. **标记**：标记出该术语
2. **确认**：向用户确认"这个概念需不需要展开"
3. **展开**（用户确认后）：一半严肃定义 + 一半类比或具体例子
4. **跳过**（用户确认不需要后）：继续推进

哪些概念需要展开，不硬性界定，随 run 次数增多逐步积累经验。
```
