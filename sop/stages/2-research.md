# 阶段 2：搜索、判断与收尾（opening → done）

> 适用：开题门通过后，直到研究完成。搜索轮次不固定。

---

## 检索面设计

先分 4 个检索面：
- 官方 / 原始
- 市场 / 新闻
- 学术
- 社区 / 案例

再给每一面分角色：
- 哪些面负责第一轮建图
- 哪些面负责找现实摩擦 / 原始规则 / 动作条件
- 哪些面只在后续轮次补关键缺口时开启
- 哪些面只能当线索，不能直接支撑判断

> 先设计检索面，再搜索；AI 摘要只能做入口，不能代替证据压缩。

---

## 搜索——建立全貌

目标是：
- 看看大家怎么讨论这个问题
- 找到主流观点 / 路径 / 方案
- 发现自己还缺哪些背景信息
- 让问题本身变得更清楚

常见动作：宽搜、看多种来源、初步分类观点、在搜索中补 context。

### 子课题拆分（持续触发）

研究过程中发现需要独立搜索/验证的子问题时，即时向用户提示是否拆分。这不是一次性动作——在 midway 之后的搜索中发现新的子课题，仍应提示用户。

---

## 提取观点、逻辑、支撑

看到成熟观点后，不要只收藏链接。至少拆成：
1. 它的结论是什么
2. 它的逻辑链条是什么
3. 它的支撑事实 / 数据 / 例子是什么
4. 它依赖哪些前提

研究真正有价值的地方不是知道"谁说了什么"，而是能说清：
- 他为什么这么说
- 他的说法靠什么站住
- 他的说法在哪些条件下才成立

---

## 主动找反对意见和攻击点（硬要求）

如果有一个观点 A：
- 看支持它的人在说什么
- 也必须看反对它的人在攻击什么

重点问：
- 反对方是在打逻辑，还是在打事实？
- 反对方打到的是边缘点，还是核心前提？
- 这些攻击成立吗？

反对意见通常更切中要害，能帮助识别哪些因素更主导、哪些理由只是表面上有说服力、哪些结论在关键前提上其实很脆弱。

---

## Motivation 校准（midway 前硬要求，之后可继续）

第一轮建图完成后、写判断单前，用搜到的关键发现反问用户：
- "这些发现跟你的实际处境/动机有什么关系？"
- "有没有什么约束是你之前没提到的？"

用户补充的约束记录到 `notes/task-card.md` 的 motivation 区域。

> motivation 不是开题时一次性写完的。用户看到搜索结果后才会联想到关键约束。midway 之后如果有新发现，仍可再做 motivation 校准。

---

## 中途门检查（midway 前必做）

### 子课题拆分兜底
- 如果之前未主动触发过拆分提示，在此处最后检查一次
- 是否发现某个子概念需要独立研究才能支撑母课题结论？
- 是否有子领域的复杂度超出当前 run 的动作上限？

### 判断单（必写）
至少写清：
- 当前判断
- 当前最值得继续看的路径
- 最短证据链
- 首个不可信信息跳点
- 待证点 / 竞争判断

**没写判断单，不进入后续补缺轮。**

### 过门：midway

写完 `notes/judgment.md` 后，执行：

```powershell
Update-QueueGate -RunId <id> -Gate midway
```

---

## 后续轮次：只补关键缺口

只补会改变路径排序或动作选择的缺口：
- 一手 / 高信任来源
- 真正会改变路径比较结果的关键变量
- 能确认或打掉竞争判断的证据
- 机制 / 文献 / 方法层面的必要补证（按需开启学术支路）

> midway 之后发现需要 motivation 校准或子课题拆分的，仍然随时提示用户。

---

## 形成综合判断

至少要形成：
- 当前最可信的判断是什么
- 这个判断成立的前提是什么
- 哪些因素更主导
- 哪些分歧暂时无法裁决
- 哪些部分只能交给事实继续验证

复杂系统里，很多问题在当下不可能被彻底判死。综合判断允许保留：暂时未决、需要继续观察、只有实践后才能验证的部分。

### 证据链要求

每条来源不仅列名字，还要说明：
- 这个来源说明了什么
- 为什么它支撑这个结论
- 它的证据层级（一手/二手/综述/社区经验）

### 路径定义要求

每条待比较路径必须写明：
1. 人类具体做什么操作
2. 人类不做什么
3. 与相邻路径的分界线

如果两条路径的区分维度不清，先明确区分标准再比较。

## 收口：memo → 用户审阅 → output

### memo（`notes/memo.md`）

收口的中间产物，面向研究者自己。必须写清：
- 当前判断 + 最短证据链
- 路径分流：推进 / 继续比较 / 暂缓 / 放弃
- 当前证据可支持到的动作上限
- 最小下一步 + 暂不动作
- 观察信号 + 推翻条件

**写不出动作上限或路径分流，就还没收口。**

### 用户审阅（阻塞点）

**memo 写完后必须交用户审阅确认，然后才能开始写 output。不得在同一轮动作中连续产出 memo 和 output。**

### output（`output.md`）

最终投递到 wiki inbox 的成品，由 memo 加工而来，面向读者。禁止将 memo 直接复制为 output。output 必须经过加工：
- 重组结构（从研究过程叙述改为结论先行）
- 补充对读者的上下文说明
- 展开关键概念
- 移除研究过程性内容（如"第一轮发现..."）

### 转成动作

如果问题已经被回答到足够支持行动，就不要继续无止境搜下去。output 中应明确写出：
- 当前结论 + 推荐路径
- 最小下一步动作
- 需要观察哪些信号
- 哪些事实会推翻当前判断

> 研究 → 判断 → 行动 → 反馈 → 再修正

### 过门：done

写完 `output.md` 后，执行：

```powershell
Update-QueueGate -RunId <id> -Gate done
```

---

## 补查（可选）

output 交付后用户基于实践发现需补充细节时，在现有 run 目录修补 output.md，log.md 记录 `amendment | detail=<补了什么>`，重新 deliver。如果补查发现核心判断有误，按 rerun 处理。
