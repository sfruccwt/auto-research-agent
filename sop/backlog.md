# SOP Backlog

## 待改进

- [ ] 开题卡：关键词压测 — 对"要回答的问题"中每个关键词做范围确认，特别是主语（谁）、领域（在哪）、动作（做什么）。必要时主动反问用户确认范围。（来源：ai-trust-layer 研究，"人机协作"应压到"vibe coding / 软件开发"）
- [ ] 搜索路径：社区/案例面默认开 agent-reach 路搜索，与 WebSearch 路并行。WebSearch 部分引擎返回摘要有信息损耗，论坛类平台搜不深。在任务卡"优先开的检索面"下补工具分配行。（来源：ai-trust-layer 研究，agent-reach 路捞到的一线讨论远比 WebSearch 路丰富）
- [ ] Motivation 持续捕获机制 — motivation 不是开题时一次性写完的，用户在中途看到搜索结果后会联想到关键约束（如"我做个人工具不是生产级产品"），这些约束会显著改变判断方向。SOP 应支持：(1) 第一轮建图后、写判断单前，用搜到的关键词反问用户"这些跟你的实际处境/动机有什么关系？"做 motivation 校准；(2) 用户随时补充的 motivation 被记录并反馈到研究方向调整。不要把 motivation 锁死在开题门。（来源：ai-trust-layer 研究，用户在中途补了"个人工具/自用 demo"约束，直接改变风险评估和路径推荐；用户建议在广搜定基线后插入 motivation 反问环节）
- [ ] 路径定义清晰度 — 待比较路径如果粒度相近（如 A"实现逻辑层" vs B"架构块层"），必须明确排序标准和区分维度，不能让用户猜。每条路径至少写：(1) 人类具体做什么操作；(2) 人类不做什么；(3) 与相邻路径的分界线。（来源：ai-trust-layer 研究，A/B 路径定义混淆导致判断方向反转）

- [ ] 备忘录/产出物的核心概念必须展开 — 如果结论中出现一个关键概念（如"生成时结构约束"），必须在备忘录中紧跟着回答：(1) 这具体是什么？(2) 怎么做？(3) 为什么这样做有效？不能只给结论不给内容。证据链同理：不能只列来源名字，要扣到"这个来源说明了什么、为什么支撑这个结论"。（来源：ai-trust-layer 研究，用户反馈备忘录核心概念悬空、证据链没扣紧）
- [ ] 备忘录 vs output 文件区分 — 备忘录（memo）是收尾门的中间产物，放 `notes/memo.md`；`output.md` 是最终投递到 wiki inbox 的成品，由备忘录加工而来。不要把中间产物直接写到 output 位置。（来源：ai-trust-layer 研究）
- [ ] 不可靠信息直接删除，不展示 — 如果判定某条证据不可靠（样本偏差、不可外推等），直接从备忘录中删掉，不要设"不可信信息跳点"一节展示给用户。用户不需要看你认为不可靠的东西。进一步：考虑从 `sop/templates.md` 的判断单和备忘录模板中也去掉"首个不可信信息跳点"字段——待确认后执行。（来源：ai-trust-layer 研究）
- [ ] 备忘录模板增加"关键概念展开"区块 — 当判断或结论中出现对无背景读者不自明的关键术语时（如"生成前约束"），备忘录应紧跟该术语设一个展开小节，回答：(1) 具体是什么；(2) 怎么做 / 写到什么程度；(3) 为什么有效。这不同于已有的"核心概念必须展开"改进项（那条侧重于不能悬空），本条侧重于在模板层面给出结构化位置，让写作者有位置放名词解释，避免关键术语只出现在结论里而读者无法理解。（来源：ai-trust-layer 研究，"生成前约束"一词经三轮补写才达到可操作程度）
- [ ] 开题卡迭代式填写 — 当用户对研究主题不熟悉时，"真正要回答的问题"不能由 AI 凭预训练知识单方面预填（可能抓错重点）。应先写粗粒度版本（如"整个 workflow 是什么"），第一轮建图后再反问用户来细化。开题卡是迭代产物，不是一次性填完的。（来源：local-embedding-gpu-deploy 研究，用户反馈"你不会抓错重点"的搜索思路——先查一轮再细化问题）
- [ ] 产出后追问/补查机制 — 研究已走到备忘录/output 阶段后，用户可能基于实践暴露出新问题来追问（如版本兼容性细节）。这类追问不够格开新 idea，但需要补充到已有 output 中。待决：(1) 追问后是回退到开题重走，还是在 output 基础上修补？(2) 修补会不会反过来影响开题卡/判断单的一致性？(3) 是否需要一种"补查"状态（轻于 rerun、重于不管）来处理这类边界情况？（来源：local-embedding-gpu-deploy 研究，用户在 output 阶段反馈实践中遇到的版本号问题，不值得开新 idea 但需要补完）
